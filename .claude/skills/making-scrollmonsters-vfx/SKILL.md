# Making ScrollMonsters VFX

## Overview
Effects are Pixel Composer projects **generated by Python scripts** (never hand-built graphs), exported to PNG strips + JSON that the Phaser game loads. Everything needed is in the repo; read `scripts/pixelcomposer/EFFECTS_GUIDE.md` before building anything new — it holds the node-slot facts and gotchas below in full.

**For detailed effects, the reference is `/Applications/PixelComposerExamples/Complex`** (Fire-Tornado, Rocket-Thrust, Lava-Floor, Spark-Bolt, Black-Hole, Icicle). Each layers several distinct elements (drawn geometry and paths, crafted sprites fed to particles, cellular structure, light seen through other layers), and each element has its own pipeline. Study their wiring (EFFECTS_GUIDE §3) and copy working sub-graphs with `Rich.borrow_tree`. One noise field tweaked across near-identical nodes reads as a smudge.

## Conventions (decided with the user — don't re-ask)
- **Palette: Toasted40 + pure white** (`palettes/Toasted40W.hex`, fxlib default) for the existing sheets. Blue `#78949b`; greens `#7b7460`, `#545955`. Rarity: common `#78949b`, rare `#8973ab`, legendary `#f7b750`. Effects "tinted in code" are pure white. **Detailed attack FX use Apollo** (`palettes/Apollo.hex`, richlib default): Toasted40 has too few cool colours for ice, lightning, water or void.
- **Ground perspective is ¾ top-down: ellipses 3:2** (2:1 iso is too flat); height goes straight up the screen. Characters 16×16–16×32. Don't shrink canvases to character size — it looks "way too pixelated".
- **Whole-number scales only.** Author an effect at the size it appears on screen and show it at 1x (`px` in the JSON). Never author a sheet expecting the game to enlarge it, and never scale a sheet to fit a gameplay radius (upgrades that grow an area may stretch it a little). If an effect needs more detail, make the canvas bigger. Older sheets are shown at their own whole-number scale (world 2×, UI 4×).
- **One sheet per attack or lasting area**, covering every phase (wind-up through hit, ignite plus a seamless loop). The game indexes it by progress or loops it and fades it out; no Start/Loop/End trios.
- **Output contract:** horizontal strip, equal frames, no spacing; JSON with `image, frame_width, frame_height, frame_count, layout, fps, duration_s, loop, anchor, palette, notes, smoothing` (`fxlib.finish` writes it).
- Semi-transparent pixels and blank first/last frames are fine. The game has its own fonts — don't make fonts.
- Dynamic things (homing trails, progress bars) stay in game code; ship pieces the game places (pips) or frames it indexes by progress (e.g. `Capture_Fill`).

## Workflow with the user
1. Read the request/spec; ask only what changes the build (one question at a time).
2. Present a short design (sizes, frames, fps, colors, anchor). **After the user approves, build without further check-ins.**
3. For a detailed effect, first dump the closest Complex example's nodes in dataflow order (EFFECTS_GUIDE §3) and plan the effect as distinct elements, each with its own pipeline. Build each effect on its own; don't make one and "script the rest".
4. Write/extend a `build_*.py` using `fxlib` / `richlib`; save to a **new** file name — never overwrite a `.pxc` the user edited by hand (check mtimes, back up to `output/pixelcomposer-backups/`).
5. Reload-and-diff the saved file; confirm all shape colors are in the palette.
6. The user checks output in Pixel Composer themselves (faster for them) and exports. Headless rendering is broken, so you build blind: ask for the export and **read the exported PNG** (crop and enlarge frames with PIL) before changing anything. Only export via screen control when asked.
7. Report a short table of what changed + what to look for. Update `assets/fx/README.md`.
8. Keep only approved work in builders, docs and examples: move rejected versions to an `_archive/` folder or delete them. Rejected examples left in context steer the next attempt the wrong way.

## Export (only when asked)
Headless CLI is broken (v1.22.10). Launch one window per file (`/Applications/PixelComposer.app/Contents/MacOS/PixelComposer <path-without-spaces>`), make sure it's the only Pixel Composer running, **press play through the whole animation**, then Rendering → Export All. Sprite sheets only collect frames that played. Verify each PNG against its JSON.

## Common mistakes (all happened here)
| Mistake | Fix |
|---|---|
| Guessing what an input slot means | Look it up in the label map |
| Shape fills the whole canvas | Positioning Mode slot 15 must be **0** (Area); templates are 2 |
| Donut rim comes out a solid disc | Inner Radius (slot 5) = **thickness**; ~0.1 is a thin ring |
| Shape won't rotate | Use slot **19** "Shape Rotation", not slot 7 |
| Transparent shape color draws opaque | Fade/hide layers with Blend opacity (`stack(..., show(...))`); start from `P.empty()` |
| Fake 3D edge splits from the face | Stack several copies at sub-pixel offsets |
| Stars/shapes under ~2 px vanish | Draw tiny sprites by hand in `build_fillers.py` |
| Squash inside a Feedback loop compounds | Put one-time transforms after the loop |
| Misreading vague feedback ("go back", "bigger") | Ask one short question before rebuilding |
| One noise × envelope → threshold → ramp, tweaked across near-identical nodes ("a smudge") | Layer distinct elements the way the Complex examples do; borrow their working sub-graphs |
| Recolouring an example and calling it a new effect | Build a new graph from the examples' techniques |
| Drawing a small sheet and scaling it up in game (1.5×, 2.03×, stretched arcs) | Author at on-screen size, show at a whole-number scale; tile long links instead of stretching |
| Changing settings by guesswork when an element renders wrong | Read the app's shader source (`strings game.ios`) or the label map, and look at the exported frames |
